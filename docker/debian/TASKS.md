# Docker image size reduction — task tracker

Target: `ghcr.io/zgornel/datalinter-compiled`. Design, evidence and verification
procedures are in [docs/docker-image-reduce-size-TECH-DESIGN.md](docs/docker-image-reduce-size-TECH-DESIGN.md);
the section references in **Details** point there.

**Baseline: 1217.67 MB compressed, 22 layers** (measured from the published
manifest). Sizes below are **compressed MB**, i.e. pull size, the same metric as
the baseline. A negative number means the task *adds* bytes.

Task numbering: `1.x` and `2.x` are the planned milestone steps, `Ax` are action
points carried out of the design review, `Bx` are bugs and issues discovered
while implementing.

## Totals

All figures below are measured, not estimated.

| | Compressed MB |
|---|---|
| Baseline, published | 1217.67 |
| Non-bundle payload (tasks 1.1–1.8) | 625.96 → **39.4** |
| App bundles, as built today | **591.0** |
| App bundles, hardlink-deduped (task 1.9) | 591.0 → **472.7** |
| App bundles, deduped + `--strip-metadata` (task 2.3) | 472.7 → **413.0** |
| **Total after Milestone 1** | **512.1 (−57.9%)** |
| **Total after Milestone 1 + task 2.3** | **452.4 (−62.8%)** |
| Remaining if 2.4 is done later | −155 (est.) → ~297 |

Task 2.3's 59.7 MB is implemented and measured but **not yet in the published
image** — it reaches the artifact only when B5 lands.

Cross-check on the method: the app bundles as built on this machine tar+gzip to
**591.0 MB**, against **591.52 MB** for the same two layers in the published
manifest — so the local measurements and the published baseline are directly
comparable.

Uncompressed, for on-disk footprint: the two bundles are 2218.2 MB as built,
1859.9 MB deduped, and 1611.9 MB deduped plus stripped. `sys.so` alone is
749.2 MB per bundle before stripping and 625.5 MB after, which is why it is the
only remaining large target (task 2.4).
